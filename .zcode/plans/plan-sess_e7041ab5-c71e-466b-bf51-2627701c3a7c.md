# Buat App `affiliate` Currency-Sensitive + Anggaran Conversion

## Masalah
travel_booking kini keluarkan SO dalam currency company masing-masing (MYR/SGD/IDR, `conversion_rate=1.0`). App `affiliate` buta currency — komisen, baki, payout dan paparan portal boleh campur MYR+SGD+IDR secara senyap. **Pembaikan dalam app `affiliate` sahaja; travel_booking tidak disentuh.**

## Prinsip
- **Jumlah sebenar** sentiasa dalam currency asal transaksi (perakaunan tidak pernah ditukar).
- **Anggaran conversion** (≈) dipapar sahaja, dikira masa-baca menggunakan kadar ERPNext Currency Exchange; tiada kadar → anggaran disembunyikan, bukan error.

## Perubahan

### 1. Tag currency pada komisen
- Medan **`currency`** (Link→Currency, read-only, default MYR) pada **Affiliate Commission** & **Affiliate Commission Invoice** (child).
- `create_commission_if_eligible` & reversal (`affiliate/api/commission_sync.py:190-250, 464-524`): set dari `so_doc.currency` / SI `currency`.
- Patch migrasi (`patches.txt` kini kosong): backfill row sedia ada dari currency SO pautan, fallback currency company default; idempotent.

### 2. Payout satu-currency
- Medan **`currency`** pada **Affiliate Payout**.
- `request_payout` (`portal_api.py:425-455`) & `generate_payout_batch*` (`payout_batch.py`): hanya agregat komisen satu currency; campuran ditolak dengan paparan baki per currency. Semakan `minimum_cashout` dalam currency payout.

### 3. Default currency affiliate + baki per-currency + anggaran
- Medan **`default_currency`** (Link→Currency, default currency company) pada **Affiliate Profile** — currency pilihan affiliate untuk paparan anggaran.
- Child table **`Affiliate Currency Balance`** (`currency`, `total_sales`, `total_commission`, `available_balance`) pada Affiliate Profile.
- Medan anggaran pada Affiliate Profile: **`total_sales_est`, `total_commission_est`, `available_balance_est`** (Currency, options=`default_currency`) — jumlah semua currency ditukar ke `default_currency`.
- Helper baharu `affiliate/api/currency_exchange.py`: kadar dari ERPNext `Currency Exchange` (for_selling, tarikh hari ini) dengan cache Redis; pulangkan `None` jika tiada kadar. Fallback kadar berpasangan melalui MYR/USD jika perlu.
- `update_affiliate_cached_totals` (`commission_sync.py:527-574`): kira per-currency → sync child table + kira anggaran ke `default_currency`.

### 4. Portal ikut currency sebenar + anggaran
- Server (`portal_api.py`): ganti `fmt_money(currency="MYR")` (:432-433) dengan currency row sebenar; dashboard/payouts summary pulangkan breakdown per-currency **plus** baris "≈ Jumlah dalam {default_currency} (anggaran)".
- JS (`affiliate-portal.js:49-51`): buang prefix `"RM"` keras; `fmt()` guna simbol currency dari API; label anggaran jelas (contoh "≈ RM 1,250.00 (anggaran)").

## Pengujian
- Unit test: komisen SO SGD ditag SGD; payout campur ditolak; totals per-currency betul; anggaran dikira betul bila kadar wujud & disembunyikan bila tiada; backfill patch idempotent.
- `bench --site dev.rpwp.my migrate` + smoke test portal dengan komisen MYR & SGD.

## Tidak diubah
Model currency axis travel_booking, hook Payment Entry kedua-dua app, logik kelulusan Gross/Nett sedia ada (approval & coverage sentiasa dalam currency asal).
